# P09: Bring the `acs` TUI up to the UX bars

- **Edge or parity:** PARITY on having a TUI (Hermes ships a TUI, a dashboard and a desktop app; `hermes-delta.md` row 12). The owner cares most about this surface, and the README GIF comes from it. An edge is possible only if it meets the bars below on measured evidence: Hermes's own UX complaints (slow first start, flicker) come from secondary sources and are not verified here.
- **Cost:** M.
- **Risk:** medium (depends on merging `main` into `rust-port`; TUI behaviour is hard to test).
- **Targets:** Rust (`rust/src/app.rs`, branch `rust-port`).
- **Status:** proposed.
- **Depends on:** P02 step 7 (merge `main` into `rust-port`), P05 (stuck, needs-me and cost queries; the Rust bus already has `stalled_tasks`).

## Problem

The TUI is a single screen of three panes (agents, open tasks, messages) plus popups. It does not show what is stuck, what needs the operator, or what the run costs. It is never tested, it wakes 40 times a second while idle, it shows stale relative times when idle, and at 80 columns its hint line and task state column are cut off. Nothing on screen links to an event sequence number except one message popup.

## Evidence

All from `rust-port` at `c6df26b` (scan, `rust/src/app.rs` unless noted):

- Layout: three panes at 28%, 36%, 36% width, a 3-row input, a 1-row hint line and a 1-row status (`:459-480`). Modes: Navigate, PickRecipient, ComposeSubject, ComposeBody, TaskTitle, AgentName, AgentRole, ConfirmCancel, Detail, Help, Setup (`:160-172`). Keys at `:1014-1165`; hints at `:792-818`; help popup 22 lines (`:892-922`).
- 80x24: no minimum-size check. The Agents hint line is about 85 characters and truncates at 80 columns (`:792-818`). A task row needs `#id` + 20-character title + 12-character assignee + state, wider than a ~29-column pane, so the state is clipped (`:620-650`).
- Idle behaviour: draws only when `dirty`, which is correct, but the loop wakes every 25 ms (`:1236-1277`; watcher min poll 25 ms, `:1186-1192`; `rust/src/watcher.rs:3-8`). Time-derived text (relative ages, online/offline computed at render with `now`, `:121-135`, flash expiry `:821`) is only re-evaluated when something else marks dirty, so an agent that goes stale stays shown as online until a key press or a bus change.
- State loaded: agents, up to 200 open tasks, the latest 50 messages; never the `events` table (`:45-94`). No stalled view (`stalled_tasks` exists, `rust/src/bus.rs:1311`), no submitted-for-review highlighting, no cost.
- Seq links: only the message popup shows `Message #<seq>` (`:938-950`); the task popup shows title, state, assignee, updated.
- Tests: `rust/tests/` has 46 `#[test]`s, none for the TUI (scan counts: bus 18, supervise 9, mcp 6, wait 6, dashboard 3, claim_race 2, import 2).
- AGENTS.md bars: one screen answers stuck/needs-me/cost; install to first accepted task in under 5 minutes; usable at 80x24 keyboard-only; zero redraws when idle, measured; every on-screen state links to an event sequence number; every UI PR carries a recording.

## Change

1. **Header strip (top row)** with three facts in words, from P05's queries: `stuck 2 · needs you 1 · spent $4.10 of $60`. `Tab` focuses a "Needs you" list (submitted tasks to review, escalations, unroutable reviews); accept/revise from the TUI uses `reviewTask` with `--why` prompt (P08). The existing three panes stay.
2. **80x24 audit.** A minimum-size guard ("needs 80x24") and a layout that fits: collapse Messages into a toggled pane below 100 columns, truncate with an ellipsis, put the state before the title in task rows. A `TestBackend` render test per mode at 80x24 asserts no clipped state column and that the hint line fits.
3. **Idle cost, measured.** Replace the 25 ms timer poll with a blocking wait on the watcher with a timeout set to the next time-based change (next agent deadline, flash expiry, or a 30 s tick for ages), and count wakeups and draws in a debug counter exposed as `acs --stats`. Target for the bar: zero draws while idle for 60 s with no bus change, and at most 2 wakeups per second; write this as a test with an injected clock.
4. **Event links.** Every task and agent row carries `#seq` of its last event; the detail popup lists that entity's last 10 events (kind, actor, seq). `x`/`Enter` on a stuck item opens its trace.
5. **Pause/resume and requeue** keys (`p`, `u`, `R`) call the same bus functions as the CLI (P07).
6. **Recording.** The PR includes an asciinema or GIF recording at 80x24, regenerated by a script in `rust/`, since the hero GIF is part of what the README claims.

## Cost

About 400 lines Rust in `app.rs` (header, needs-you list, layout, event popup, stats) plus 10-15 render tests. The prior merge of `main` into `rust-port` is a separate, mechanical cost (P02).

## Risk

- **Slop risk (AGENTS.md):** a header of counts can become decoration. Each number must answer a question and link to the list behind it; no tiles, no colour-only meaning.
- **Test fragility:** render tests against exact strings break on every change. Assert layout properties (no truncated state column, hint fits) rather than snapshots.
- **Scope drift:** the TUI is a console for operation, not a chat client. Compose stays minimal.
- **Dependency:** P02 step 7 must land first; the TUI queries rely on code on `main`.
- **Two UIs:** the web dashboard (P10) must show the same three answers; build both from the same queries so they cannot disagree.

## How it is verified

- `cargo test --manifest-path rust/Cargo.toml` with the new `TestBackend` tests for 80x24 in each mode.
- Idle-redraw test: with the injected clock and a fixture bus, advance 60 s with no change and assert draws == 0 and wakeups under the stated bound; the same figures printed by `acs --stats` on a real machine.
- Interop: a bus mutated by the TS CLI changes the header counts within the watcher interval (`scripts/v2-interop-smoke.mjs` extended).
- First-run time: a stopwatch run from `cargo install` (or release binary) to first accepted task, recorded in the PR, against the 5-minute bar. Not runnable in a web session.
- Recording attached to the PR.
